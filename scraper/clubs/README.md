# הגדרות המועדונים

כל קובץ כאן מתאר מועדון אחד. זה המקום היחיד שצריך לערוך כשאתר משנה
את עצמו והסריקה נשברת — הקוד ב-`scraper/` נשאר כמו שהוא.

## למה הבוררים ריקים

אתרי המועדונים חסומים מסביבת הפיתוח שבה נבנתה המערכת, ולכן אי אפשר
היה לקרוא את ה-HTML האמיתי שלהם ולכתוב בוררים מדויקים. `login.js`
מנחש לבד: שדה סיסמה, שדה משתמש, כפתור שליחה ושדה קוד מזוהים לפי
הסוג והתפקיד שלהם, מה שעובד ברוב האתרים.

`selectors` בקובץ הוא **עקיפה**, לא דרישה. משאירים ריק, מריצים,
ומוסיפים בורר רק למה שנכשל.

## שדות

| שדה | משמעות |
|---|---|
| `id` | מזהה פנימי |
| `provider` | חייב להתאים ל-`id` של ספק ב-`benefits/data/benefits.json` |
| `name` | השם שמופיע בהודעות ובבקשת הקוד |
| `requiresLogin` | `false` = עמוד ציבורי, נסרק בלי סיסמה ובלי קוד |
| `loginUrl` | עמוד ההתחברות |
| `pages` | עמודים לסריקה. `kind`: `benefits` או `status` |
| `userEnv` / `secretEnv` | שמות משתני הסביבה. **הערכים עצמם לעולם לא כאן** |
| `selectors` | עקיפות בלבד. כל שדה מקבל בורר או מערך בוררים |

## איך מוסיפים בורר

פותחים את האתר בדפדפן, לוחצים ימני על השדה שנכשל, "בדיקה", ימני על
השורה המסומנת → Copy → Copy selector. מדביקים:

```json
"selectors": { "otp": "#verification-code-input" }
```

## הבנקים

`discount_bank`, `onezero` ו-`discount_green_wallet` מסומנים
`requiresLogin: false` **במכוון**. אריק ביקש במפורש שהמערכת לא תתחבר
לחשבון הבנק שלו אלא רק תאסוף את ההטבות. העמודים האלה הם קטלוג
ציבורי, ואין להם משתמש או סיסמה בשום מקום במערכת.
